# GitHub 공개 전 점검

범위: 실제 계정 시연 검증, 미완성 화면 정리, 오류 수정과 배포. GitHub 공개 전환 및 영상·발표 PDF·제출 TXT 제작은 이후 단계입니다.

## 2026-10-27 현재 상태

- 프로젝트·프로토콜·일정·회원 인증 기능은 구현되어 있습니다.
- 데이터 분석·고정 응답 AI·설정 메뉴와 편집 기능이 없는 진행률·상태 표시는 제거했습니다.
- 로그인 상태 확인의 예외 처리와 저장·로그인 중 중복 요청 방지를 보완했습니다.
- 배포 사이트의 로그인 화면 접속은 확인했습니다.
- Supabase health 조회는 샌드박스 안팎에서 ENOTFOUND로 실패했습니다. 관리자 로그인 후 대시보드에서 실제 Paused 상태를 확인했고, 기존 프로젝트의 Resume을 실행했습니다. 복원 완료 후 로그인·저장을 재검증합니다.
- 정리한 제출 버전 `b0e43b9`의 Vercel Production 배포가 Ready이며 운영 도메인에 연결된 것을 확인했습니다.
- 실제 계정으로 로그인 후 아래 흐름을 검증해야 합니다. 10월 6일 DB 검증 기록을 오늘의 실사용 검증으로 대신하지 않습니다.

## 실제 계정 검증 시나리오

테스트용 프로젝트 이름: `제출 전 점검 - 단진자 실험`. 실제 연구 기록을 덮어쓰지 않습니다.

1. 기존 계정으로 로그인합니다. 처음 가입한다면 이메일 확인 메일이 수신되는지 확인합니다.
2. 새 프로젝트에 제목과 연구 주제를 입력합니다. 시작일보다 빠른 마감일을 넣으면 저장이 차단되는지 확인한 뒤 정상 날짜로 저장합니다.
3. 프로젝트 검색에 이름 일부와 분야를 입력해 결과를 확인합니다. 없는 검색어의 빈 결과도 확인합니다.
4. 프로젝트에서 실험 목적과 두 단계를 입력합니다. 준비물·장비·조건·주의 사항을 입력하고 순서를 바꾼 뒤 저장합니다.
5. 새로고침 후 같은 프로젝트를 열어 목적·단계 내용·순서를 확인합니다. 시험용 단계를 하나 추가·삭제하고 다시 저장합니다.
6. 연구 일정에서 시험용 일정을 추가하고 제목·날짜·시간·메모를 수정합니다. 완료와 미완료를 바꾸고 새로고침하여 유지되는지 확인합니다.
7. 이번 점검에서 추가한 시험용 일정만 삭제하고 새로고침하여 사라지는지 확인합니다. 기존 일정은 삭제하지 않습니다.
8. 프로토콜을 조금 수정한 뒤 이동해 저장 전 확인 메시지에서 취소했을 때 화면이 유지되는지 확인합니다. 변경을 저장합니다.
9. 두 번째 시험용 프로젝트를 만들고 기록이 섞이지 않는지 확인합니다.
10. 로그아웃하고 다시 로그인하여 저장했던 프로젝트·프로토콜이 유지되는지 확인합니다.

## 계정·서비스 설정

- LabFlow 앱 계정과 Supabase 관리자 계정은 별도입니다.
- Supabase 관리자 로그인이 만료되었다면 Dashboard에서 기존 계정으로 로그인합니다.
- Paused 상태라면 기존 프로젝트를 복원하고 Ready 상태가 된 뒤 다시 시도합니다. 새 프로젝트를 만들거나 DB를 초기화하지 않습니다.
- API URL과 Publishable key는 같은 프로젝트의 값이어야 합니다. 주소나 키가 변경되었다면 Vercel 환경 변수를 수정하고 재배포합니다.
- 이메일 인증과 사용자별 RLS는 유지합니다. 비밀번호는 채팅에 적거나 저장소에 기록하지 않습니다.
