# 5회차: 팀 공동 편집과 수정 이력

회원가입은 기존 이메일·비밀번호 방식이며 이메일 확인은 끈 상태를 유지한다. 메일 발송 서비스 연결은 사용자가 취소했다. 공동 편집 기능과 별개이다.

## 사용 방법

1. 프로젝트 소유자는 프로젝트 → 연구 관리 → 팀원·초대에서 초대코드를 발급한다.
2. 코드를 팀원에게 직접 전달한다. 코드는 7일간 유효하고 한 번만 사용할 수 있으며 원문은 발급 직후에만 표시된다.
3. 팀원은 자기 계정으로 로그인하고 프로젝트 목록의 팀 참여에 코드를 입력한다.
4. 공유 프로젝트에서 연구 현황·설계, 프로토콜, 일정, 측정 데이터, 사진 분석, 참고문헌, 재현성 기록을 조회·수정한다.
5. 소유자는 팀원 권한을 해제하거나 미사용 초대를 취소할 수 있다. 프로젝트 휴지통 이동·복원은 소유자만 가능하다.
6. 연구 관리 → 수정 이력에서 수정자 이메일, 시각, 기록 종류, 변경 항목을 확인하고 상세에서 변경 전후 값과 JSON을 내려받는다.

## 공동 편집 범위와 충돌

저장한 기록을 공유하는 방식이다. 실시간 글자 단위 병합·커서 공유는 제공하지 않는다. 프로젝트를 연 동안 15초 간격으로 다른 사용자의 저장을 확인해 알리고, 최신 내용 불러오기로 갱신한다. 작성 중인 내용이 있으면 먼저 저장하거나 복사·취소해야 한다.

각 행의 revision과 원자적 조건부 갱신으로 오래된 화면의 저장을 거부한다. 같은 연구 설계 JSON에 담긴 참고문헌·사진 분석·재현성 기록 사이에도 충돌 검사가 적용된다. 기본 정보와 연구 설계 저장은 두 요청이므로 일부만 저장되면 이를 명시한다.

이력은 DB 트리거가 기록하므로 일반 클라이언트가 생성·수정·삭제할 수 없다. 적용 이후 저장부터 쌓이며 과거 수정 내역을 소급 복원하지 않는다. 현재 값이 실제로 바뀌지 않은 저장은 이력에 남기지 않는다. 기록의 자동 되돌리기는 제공하지 않는다.

## DB 및 검증

- 기존 DB: `supabase/migrations/20261117_collaboration.sql` 실행. 새 DB: `supabase/schema.sql` 전체 실행.
- 역할별 검증: `tests/collaboration-rls.sql`을 SQL Editor의 관리자 연결로 실행. 임시 사용자·프로젝트·초대·이력을 전부 롤백한다.
- 소유자/팀원/외부인 RLS, 코드 일회 사용, 팀원 해제, 이력 전후 값·삭제 기록, 이력 변조 차단, 토큰 해시 접근 차단, revision 충돌과 CAS, 익명 접근 차단을 검사한다.
- `npm test` 29개, TypeScript, 변경 파일 Oxlint, Vercel 빌드로 기존 기능과 형식을 점검한다.

초대코드를 받은 로그인 사용자는 프로젝트 전체 기록과 팀원 이메일을 볼 수 있으므로 참여시킬 팀원에게만 전달한다. 이메일 소유 확인을 사용하지 않기 때문에 수정자 표시는 가입 시 입력한 이메일이며 실명·이메일 소유 증명은 아니다.
